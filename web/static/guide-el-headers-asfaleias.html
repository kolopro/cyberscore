Κεφαλίδες ασφάλειας HTTP εξηγημένες

Τι είναι τα security headers, τι επίθεση αποτρέπει το καθένα και πώς να τα προσθέσεις στον server σου σε λίγα λεπτά.

Με λίγα λόγια: Τα security headers είναι γραμμές που στέλνει ο server μαζί με κάθε σελίδα και ενεργοποιούν προστασίες μέσα στον browser. Η απουσία τους είναι από τα πιο κοινά ευρήματα — και η προσθήκη τους από τις πιο γρήγορες βελτιώσεις που μπορείς να κάνεις.

Τι είναι τα security headers;

Κάθε φορά που ο browser σου ζητά μια σελίδα, ο server απαντά με τα δεδομένα της σελίδας και με κεφαλίδες (headers) — μικρές οδηγίες που λένε στον browser πώς να συμπεριφερθεί. Τα security headers είναι ένα υποσύνολο αυτών που ενεργοποιούν προστατευτικές συμπεριφορές: «μην επιτρέπεις αυτή τη σελίδα σε iframe», «χρησιμοποίησε πάντα HTTPS», «φόρτωσε περιεχόμενο μόνο από εγκεκριμένες πηγές».

Η ρύθμισή τους γίνεται στον server ή στο CDN/proxy σου και δεν απαιτεί αλλαγές στον κώδικα της εφαρμογής.

HSTS — Strict-Transport-Security

Το HTTP Strict Transport Security λέει στον browser: «Αυτός ο ιστότοπος είναι πάντα HTTPS — μην δοκιμάσεις ποτέ HTTP». Αυτό αποτρέπει επιθέσεις SSL stripping, όπου ένας επιτιθέμενος στο ίδιο δίκτυο αναγκάζει τον browser να συνδεθεί ανασφαλώς.

# Nginx
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

# Apache
Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains"
Πρόσθεσε ; preload στο τέλος και εγγράψου στο hstspreload.org για να ενεργοποιηθεί το HSTS ακόμα και στην πρώτη επίσκεψη.

Content-Security-Policy (CSP)

Το CSP ορίζει από πού επιτρέπεται να φορτωθεί περιεχόμενο (scripts, styles, εικόνες). Αποτρέπει δραστικά επιθέσεις XSS (Cross-Site Scripting), όπου κακόβουλος κώδικας εισάγεται στη σελίδα σου. Είναι η πιο ισχυρή αλλά και πιο περίπλοκη κεφαλίδα.

# Βασική πολιτική CSP (Nginx)
add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; frame-ancestors 'none'" always;
Για sites που χρησιμοποιούν Google Analytics, Fonts ή AdSense, πρόσθεσε τα αντίστοιχα domains στο script-src και style-src.

X-Frame-Options

Αποτρέπει τον ιστότοπό σου να φορτωθεί μέσα σε <iframe> άλλων domains — αποτρέποντας έτσι επιθέσεις clickjacking, όπου ο χρήστης νομίζει ότι κάνει κλικ σε ένα κουμπί του δικού σου site αλλά στην πραγματικότητα κάνει κλικ σε κάτι κρυμμένο από άλλο site.

# Nginx
add_header X-Frame-Options "SAMEORIGIN" always;

# Apache
Header always set X-Frame-Options "SAMEORIGIN"

Τιμές: DENY (δεν επιτρέπεται σε κανένα iframe), SAMEORIGIN (επιτρέπεται μόνο από το ίδιο domain).

X-Content-Type-Options

Αποτρέπει τον browser από το να «μαντέψει» τον τύπο αρχείου (MIME sniffing). Χωρίς αυτό, ένα αρχείο που ανεβάζει ο χρήστης (π.χ. μια «εικόνα» που στην πραγματικότητα είναι JavaScript) μπορεί να εκτελεστεί ως script.

add_header X-Content-Type-Options "nosniff" always;

Referrer-Policy

Ελέγχει ποιες πληροφορίες στέλνει ο browser στον επόμενο site όταν ο χρήστης κάνει κλικ σε έναν σύνδεσμο. Χωρίς αυτό, ολόκληρο το URL της σελίδας (που μπορεί να περιέχει ευαίσθητες παραμέτρους) αποστέλλεται σε εξωτερικά sites.

add_header Referrer-Policy "strict-origin-when-cross-origin" always;

Permissions-Policy

Ελέγχει ποιες λειτουργίες του browser (κάμερα, μικρόφωνο, geolocation) επιτρέπονται στη σελίδα σου. Αν ο ιστότοπός σου δεν χρειάζεται πρόσβαση σε αυτά, καλό είναι να τα απενεργοποιήσεις ρητά:

add_header Permissions-Policy "camera=(), microphone=(), geolocation=(), payment=()" always;

Πώς να ελέγξεις ποια headers σου λείπουν

Ο γρηγορότερος τρόπος: σάρωσε τον ιστότοπό σου με το CyberScore. Θα δεις ακριβώς ποια headers λείπουν, τι κίνδυνο δημιουργεί το καθένα και τις ακριβείς γραμμές ρύθμισης που χρειάζεσαι.
